このフォルダに、個別のWebUIを備えたChatbotアプリを作りたい。
これは、MCP Gatewayのデモ用です。

まずは、アプリの要件を整理します。
以下の情報を元にしますが、追加で必要な情報があれば、私に質問してください。

・WebUI、Chatbotが一体となったQuarkusのアプリケーションを作る
・ローカルでコンテナとしてテスト、検証し、最終的にはOpenShiftへコンテナデプロイできるようにする
・OpenShiftでは、rhcl-ai-bot namespaceにデプロイする
・WebUIは、OpenSHiftではhttpsでアクセスできること
・生成AIのモデルは、
RHCL_AI_OPENAI_BASE_URL=https://litellm-prod.apps.maas.redhatworkshops.io/v1
RHCL_AI_OPENAI_MODEL=deepseek-r1-distill-qwen-14b
RHCL_AI_OPENAI_API_KEY=sk-your-api-key-here
ただしこれらの変数はハードコーディングせず、環境変数を使うようにし、モデルが変わっても柔軟に対応できるようにすること。
API KEYは、OpenShiftではSecretを使うこと。

・MCPサーバは、外部のESPNのAPIをラップしたもので、
 - https://site.api.espn.com/apis/site/v2/sports/basketball/nba/scoreboard
 - https://site.api.espn.com/apis/site/v2/sports/soccer/eng.1/scoreboard
 - https://site.api.espn.com/apis/site/v2/sports/soccer/esp.1/scoreboard
 - https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard
 - https://site.api.espn.com/apis/site/v2/sports/hockey/nhl/scoreboard
 これらをベースに、期間を指定して試合の情報を取得できるものである
・MCPサーバのURLとパスは以下、ただし、これも環境変数などを用いて可変とすること。
・MCPサーバの認証は今回はない
・Chatbotは、入力されたコンテキストから、この5つのMCP toolsのどれを使うべきかを自立的に判断し、MCP serverに問い合わせ、情報を取得してからユーザーにレスポンスを返すこと。
・Chatbotは、過去の会話履歴を保存する必要は無し
・Chatbotは、日本語対応も可能とすること
